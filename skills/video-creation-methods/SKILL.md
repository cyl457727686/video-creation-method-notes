# Video creation methods

Help the user turn a shot's storytelling purpose into observable visuals and sound, using the selected model's own format. This skill prepares or reviews creative inputs; it does not provide a video-generation backend.

## Select the reference

Use the model and product entry point chosen by the user or established in the current project. If the model is missing, ask which one they intend to use before writing model-specific syntax; common storyboard work can proceed meanwhile. Do not infer a model from a case study's appearance.

- **MiniMax H3:** read [H3 methods](references/h3.md). Distinguish T2VA/I2VA/FL2VA/L2VA from Ref2VA. Use the actual mode's fields; H3 descriptions are English, while approved dialogue, lyrics and visible text retain their original language under official syntax.
- **Seedance 2.5:** read [2.5 methods](references/seedance-2.5.md). Keep reference roles and task intent explicit; API capabilities do not establish the current Jimeng UI's controls.
- **Seedance 2.0:** read [2.0 methods](references/seedance-2.0.md). Do not import H3 fields or 2.5-only audio paths, capacities or durations.

Read only the selected model reference. For generic animation design without model-specific output, use its relevant animation discussion once the model is known, or work from the shared principles below without inventing a model choice. For provenance, disputed findings, precise sound claims or claimed improvement, consult [sources](references/SOURCES.md) and [evidence limits](references/LIMITS.md).

## Apply methods to the actual task

Use the supplied story, current assets, dialogue and intended shot as the basis. Check only information that affects the result: input state, subject identity, spatial relationships, reference roles and requested changes. If text conflicts with a reference image, identify that concrete conflict before adding more preservation instructions. Do not invent uploads or material numbers.

Select relevant methods rather than applying a checklist to every shot:

- Define the visible initial state and meaningful result. For contact or fast action, preserve the necessary connection, force, direction and reaction; avoid mutually exclusive starting states.
- Describe character performance separately from camera movement. Establish starting composition, path and landing information; do not impose a sample's starting distance, foreground obstacle or face close-up on all moves.
- For animation, arrange value and edge hierarchy, spatial layers, readable key poses, and primary versus secondary movement. Choose style-specific techniques only when they match the user's approved design; do not impose matte rendering, fog, low frame rates or on-twos.
- Distinguish a speaking event and listener response from ambient sound and audience-only score. Put synchronized events in the selected model's shot description. Do not identify speakers from ASR numbering or treat guessed language, source or timecodes as approved facts.
- Diagnose input, prompt, generated clip, editing selection and final output separately. Post speed changes and untested revised prompts do not prove that a prompt caused an improvement.

The reference documents retain some original-project conventions, such as approval tracking, English Seedance descriptions and a particular independent TTS provider. Treat these as project context, not universal model rules. Follow the current user's language, asset, voice and workflow decisions; preserve actual official model requirements. Do not add a new approval chain, keyframe generation, forced durations or reference-video chaining.

## Deliver the requested result

For prompt writing, return the selected mode's usable prompt with only necessary input mappings or unresolved dependencies outside the model body. For a storyboard, prioritize visible composition, action and state handoff. For review, identify the observed issue and the layer that should change. Use the user's requested response language; the model prompt itself follows the selected model's language rules.

Check current official sources when exact syntax or capabilities matter and tools permit. If live verification is unavailable, label the saved guidance as dated rather than claiming current support. Case observations, author intent and research suggestions are not a guarantee of generation quality. Refer to the actual evidence available; never claim to have watched, heard or tested material merely because it is described in these files.

Use generation, uploads, paid services or external publishing only under the user's actual authorization. This skill alone supplies none of those permissions or tools.
